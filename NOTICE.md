## WATIsGrass (GPL-3.0)

ThruLoo's indoor, tunnel and bridge routing data comes from **WATIsGrass** by **Ricky Qin** and **Manasva Katyal**, https://github.com/rickyqin005/WATIsGrass (website: https://watisgrass.co), licensed under the GNU GPL v3.0. The repository has no separate data licence, so the data is treated as GPL-3.0.

| Path | What it is | Changed? |
|---|---|---|
| `data/indoor/watisgrass/paths.json` | WATIsGrass `web/src/geojson/paths.json` | No, byte-identical to the upstream file |
| `data/indoor/watisgrass/buildings.json` | WATIsGrass `web/src/geojson/buildings.json` | No, byte-identical |
| `data/indoor/watisgrass/FORMAT.md` | WATIsGrass `web/src/geojson/README.md` (format description) | Copied; only the file name differs |
| `data/indoor/watisgrass/LICENSE` | WATIsGrass `LICENSE` (GPL-3.0 text) | No |
| `public/data/campus.json` | Baked route graph. The indoor part is derived from the two data files above | **Yes, generated by `npm run data:bake`** |

Not copied: WATIsGrass's application code (React UI, `algorithm/dijkstra.ts`, map code). ThruLoo's reader, `src/routing/indoor.ts`, is written from scratch against the documented data format; it uses the same rule for joining features (a node is a coordinate, building and floor) and the same 14 seconds per floor figure. Routing (`src/routing/graph.ts`) is ThruLoo's own A* search.

### What ThruLoo changed (GPL-3.0 section 5a)

- The data files in `data/indoor/watisgrass/` are unmodified copies.
- `npm run data:bake` converts them into `public/data/campus.json`: coordinates are projected to local metres, WATIsGrass's outdoor "walkway" lines are dropped in favour of OpenStreetMap paths, doors to the outside are joined to the nearest OpenStreetMap entrance, floor heights are solved from the stairwell data, and the result is merged into ThruLoo's own route graph. This conversion was made from November 2026.
- Everything else in this repository was written for ThruLoo.
